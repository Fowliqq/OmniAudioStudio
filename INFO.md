## 2. Поддерживаемые аудиоформаты и алгоритмы

1. **FLAC (Free Lossless Audio Codec)**: Сжатие звука без малейших потерь. Уровень сжатия: 5 (оптимальный баланс между размером и скоростью).
2. **WAV (Waveform Audio File Format)**: Несжатый студийный мастер в формате Linear PCM (`pcm_s16le`).
3. **ALAC (Apple Lossless)**: Сжатие Apple без потерь в контейнере QuickTime / MP4 (`.m4a`).
4. **AIFF (Audio Interchange File Format)**: Несжатый Apple PCM big-endian (`pcm_s16be`).
5. **MP3 (MPEG Audio Layer III)**: Кодировщик LAME (`libmp3lame`) с битрейтом до 320 kbps, стандартизированные метаданные ID3v2.3 и ID3v1.
6. **AAC / M4A**: Нативный кодировщик `aac` со флагом оптимизации заголовков `+faststart` (мгновенное начало воспроизведения).
7. **OGG (Ogg Vorbis)**: Кодек `libvorbis` переменного и постоянного битрейта.
8. **OPUS**: Передовой IETF RFC 6716 кодек (`libopus`) с принудительной передискретизацией в 48000 Hz (согласно стандарту).
9. **WMA (Windows Media Audio)**: Совместимый кодек `wmav2` для устаревших устройств Windows Media.

## 3. Формулы динамического расчёта веса файла

Модель [`ConversionTask.cs`](file:///E:/antonantina/OmniAudioStudio-GitHub/OmniAudioStudio.Desktop/Models/ConversionTask.cs) выполняет динамический расчёт веса файла для отображения в интерфейсе до и после конвертации:

### 1. Форматы сжатия с потерями (MP3, AAC, OGG, OPUS, WMA)
```csharp
long estimatedBytes = (long)(Duration.TotalSeconds * (bitrateKbps * 1000.0 / 8.0)) + 8192;
```
*Например, 3-минутный трек при 320 kbps: $180 \times 40\,000 + 8\,192 \approx 7.2\text{ МБ}$.*

### 2. Несжатый PCM (WAV, AIFF)
```csharp
long estimatedBytes = (long)(Duration.TotalSeconds * sampleRate * channels * bytesPerSample) + 44;
```
*Для стандартного CD-качества (44100 Hz, Stereo, 16-bit): $180 \times 44100 \times 2 \times 2 + 44 \approx 31.7\text{ МБ}$.*

### 3. Сжатый Lossless (FLAC, ALAC)
Если конвертация происходит из формата с идентичным сжатием, берется исходный размер. В противном случае используется эмпирический коэффициент сжатия аудиопотока ~58% от несжатого PCM:
```csharp
long uncompressedBytes = (long)(Duration.TotalSeconds * sampleRate * channels * 2);
long flacBytes = (long)(uncompressedBytes * 0.58);
```

### 4. Фактический вес готового файла
Сразу после успешного завершения конвертации (`ExitCode == 0`), движок [`ConversionEngine.cs`](file:///E:/antonantina/OmniAudioStudio-GitHub/OmniAudioStudio.Desktop/Services/ConversionEngine.cs) считывает физический размер файла на диске:
```csharp
task.ActualFinalFileSize = new FileInfo(task.TargetPath).Length;
```
Префикс тильды (`~`) автоматически исчезает, и пользователь видит точный вес (например: `[FLAC · 982.4 KB]`).

## 4. Инструкция по сборке и релизу

### Шаг 1. Скачивание зависимостей FFmpeg
```powershell
powershell -ExecutionPolicy Bypass -File scripts\download-ffmpeg.ps1
```

### Шаг 2. Компиляция проекта
```powershell
dotnet build OmniAudioStudio.sln -c Release
```

### Шаг 3. Запуск верификационных тестов
```powershell
dotnet run --project OmniAudioStudio.Tests/OmniAudioStudio.Tests.csproj -c Release
```

### Шаг 4. Сборка единого автономного .EXE
```powershell
dotnet publish OmniAudioStudio.Desktop/OmniAudioStudio.Desktop.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -o dist
```
Результат будет расположен в папке `dist/OmniAudioStudio.exe`.

### 5.1. Ошибки кодеков и FFmpeg

#### 🔴 Ошибка 5.1.1: `FFmpegNotFoundException` / «FFmpeg не найден»
* **Симптомы:** При запуске тестов или при нажатии кнопки «Конвертировать» приложение сообщает, что бинарник `ffmpeg.exe` отсутствует.
* **Причина:** Движок `FFmpegLocator` просканировал системные каталоги, локальную папку `bin/` и переменную окружения `PATH`, но не обнаружил исполняемый файл.
* **Решение:**
  1. Выполните команду автоматической установки:
     ```powershell
     powershell -ExecutionPolicy Bypass -File scripts\download-ffmpeg.ps1
     ```
  2. Либо установите FFmpeg через системный пакетный менеджер Windows:
     ```powershell
     winget install Gyan.FFmpeg
     ```
  3. Либо вручную скопируйте `ffmpeg.exe` и `ffprobe.exe` в папку `bin/` рядом с проектом.

#### 🔴 Ошибка 5.1.2: Блокировка антивирусом Windows SmartScreen / «Mark of the Web»
* **Симптомы:** Процесс FFmpeg падает с кодом `-1073741819` (0xC0000005) или система выдает диалоговое окно «Файл заблокирован, так как получен из Интернета».
* **Причина:** Windows накладывает метку зоны безопасности NTFS (`Zone.Identifier`) на скачанные из сети бинарники.
* **Решение:**
  Снимите флаг блокировки в PowerShell:
  ```powershell
  Unblock-File .\bin\ffmpeg.exe
  Unblock-File .\bin\ffprobe.exe
  ```
  Если используется сторонняя защита (Касперский, ESET), добавьте папку `bin/` в доверенные исключения.

#### 🔴 Ошибка 5.1.3: «Invalid data found when processing input» / Повреждённый файл
* **Симптомы:** Задача завершается статусом `Failed`, во всплывающей подсказке карточки трека отображается сообщение `Invalid data found when processing input`.
* **Причина:** Исходный файл не является валидным аудиоконтейнером, был оборван при скачивании или защищен DRM (например, защищенные файлы Apple Music `.m4p` или Audible `.aax`).
* **Решение:**
  1. Проверьте целостность файла через `ffprobe`:
     ```powershell
     .\bin\ffprobe.exe "путь_к_файлу.mp3"
     ```
  2. Если файл повреждён — скачайте его заново.
  3. Если файл защищён DRM — снимите DRM перед импортом в программу.

#### 🔴 Ошибка 5.1.4: Предупреждение о битрейте OPUS (ограничение 256 kbps)
* **Симптомы:** При выборе целевого формата OPUS и битрейта 320 kbps в логе или на выходе кодек использует 256 kbps.
* **Причина:** Согласно официальному стандарту IETF RFC 6716, кодек Opus достигает абсолютной прозрачности (Lossless-эквивалент для слуха) при 192–256 kbps для стереопотока. Значения выше 256 kbps кодек игнорирует.
* **Решение:** Поведение является ожидаемым и штатным. Движок `ConversionEngine` автоматически корректирует битрейт до 256 kbps без ошибки.

#### 🔴 Ошибка 5.1.5: Отсутствие метаданных в сырых WAV файлах
* **Симптомы:** Исполнитель и название трека не отображаются в некоторых старых плеерах после конвертации в WAV.
* **Причина:** Формат WAV изначально не проектировался для хранения метаданных ID3v2, и большинство устаревших автомагнитол читает только чанк `RIFF INFO`, игнорируя ID3.
* **Решение:** Для абсолютной совместимости тегов на любых внешних устройствах выбирайте формат **FLAC** (для звука без потерь) или **MP3** (для портативных магнитол).

### 5.2. Ошибки файловой системы и ввода-вывода (I/O & Permissions)

#### 🔴 Ошибка 5.2.1: Блокировка файла другим приложением (`IOException`)
* **Симптомы:** Ошибка `The process cannot access the file because it is being used by another process`.
* **Причина:** Исходный файл воспроизводится в данный момент в стороннем плеере (AIMP, VLC, Windows Media Player) либо целевой файл заблокирован клиентом облачной синхронизации (OneDrive, Яндекс.Диск, Dropbox, Google Drive).
* **Решение:**
  1. Остановите воспроизведение в плеере или закройте его.
  2. Приостановите синхронизацию облачного хранилища для папки сохранения.
  3. Либо переключите в приложении радиокнопку «В указанную папку» и выберите локальную директорию вне зоны действия облака (например, `D:\Music_Converted`).

#### 🔴 Ошибка 5.2.2: Ограничение длины пути Windows (`PathTooLongException` > 260 символов)
* **Симптомы:** Ошибка при добавлении или сохранении трека с длинным именем внутри многоуровневой структуры каталогов.
* **Причина:** Ограничение Win32 API `MAX_PATH` по умолчанию составляет 260 символов.
* **Решение:**
  Включите поддержку длинных путей в реестре Windows (требуются права администратора):
  ```powershell
  Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name 'LongPathsEnabled' -Value 1
  ```
  После перезагрузки или перезапуска Проводника ограничение снимется.

#### 🔴 Ошибка 5.2.3: Отказ в доступе при записи (`UnauthorizedAccessException`)
* **Симптомы:** Ошибка доступа при попытке сохранить конвертированные файлы в корень `C:\`, в `C:\Program Files` или в системные папки Windows.
* **Причина:** Механизм контроля учетных записей Windows (UAC) блокирует прямую запись пользовательских процессов в защищённые системные области.
* **Решение:** Сохраняйте файлы в пользовательские библиотеки («Музыка», «Загрузки», «Документы», рабочий стол) либо на дополнительный логический диск (`D:\`, `E:\`).

#### 🔴 Ошибка 5.2.4: Коллизия имен исходного и результирующего файлов
* **Симптомы:** Пользователь конвертирует файл того же формата в исходную папку (например, `FLAC` в `FLAC` с изменением частоты дискретизации).
* **Решение:** В классе `QueueManager.ResolveSafeTargetPath` встроен алгоритм автоматического предотвращения перезаписи: если пути совпадают, к имени результирующего файла добавляется суффикс `_converted` (например, `audio_converted.flac`).

### 5.3. Ошибки сборки, NuGet, компилятора и выгрузки на GitHub

#### 🔴 Ошибка 5.3.1: `NETSDK1045: The current .NET SDK does not support targeting .NET 8.0`
* **Симптомы:** При запуске `dotnet build` сборка завершается с ошибкой неподдерживаемого целевого фреймворка.
* **Причина:** В системе установлена устаревшая версия .NET SDK (.NET 6 или .NET 7).
* **Решение:**
  Установите актуальный [.NET 8.0 SDK](https://dotnet.microsoft.com/download/dotnet/8.0):
  ```powershell
  winget install Microsoft.DotNet.SDK.8
  ```
  Проверьте установленную версию командой `dotnet --version` (должно быть `8.0.xxx`).

#### 🔴 Ошибка 5.3.2: `CS0246: The type or namespace name 'Wpf' could not be found`
* **Симптомы:** Ошибки компиляции, указывающие на отсутствие библиотек `Wpf.Ui`, `CommunityToolkit.Mvvm` или `TagLibSharp`.
* **Причина:** Пакеты NuGet не были восстановлены из-за сетевого сбоя или отсутствия подключения к глобальному реестру.
* **Решение:**
  Принудительно восстановите зависимости:
  ```powershell
  dotnet restore OmniAudioStudio.sln --force
  ```
  Убедитесь, что источник nuget.org включен:
  ```powershell
  dotnet nuget list source
  ```

#### 🔴 Ошибка 5.3.3: Ошибка публикации `PublishSingleFile requires a RuntimeIdentifier`
* **Симптомы:** Команда `dotnet publish -p:PublishSingleFile=true` падает с ошибкой требования RID.
* **Причина:** При сборке единого бинарника компилятор должен знать архитектуру целевой ОС для линковки нативных библиотек рантайма.
* **Решение:** Всегда передавайте ключ `-r win-x64`:
  ```powershell
  dotnet publish OmniAudioStudio.Desktop/OmniAudioStudio.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist
  ```

#### 🔴 Ошибка 5.3.4: Отклонение выгрузки на GitHub (`File exceeds 100.00 MB limit`)
* **Симптомы:** При выполнении `git push origin main` сервер GitHub отклоняет транзакцию:
  `remote: error: File OmniAudioStudio/bin/ffmpeg.exe is 102.82 MB; this exceeds GitHub's file size limit of 100.00 MB`.
* **Причина:** Попытка закоммитить большой исполняемый файл (`ffmpeg.exe` или готовый `OmniAudioStudio.exe`) напрямую в дерево исходного кода Git.
* **Решение:**
  1. В предоставленном репозитории уже настроен правильный файл [`.gitignore`](file:///E:/antonantina/OmniAudioStudio-GitHub/.gitignore), исключающий `*.exe`, `bin/`, `obj/`, `dist/` и `publish/`.
  2. Большие бинарные релизы не коммитятся в git-репозиторий — они загружаются в раздел **GitHub Releases (Assets)**.
  3. Пользователи и разработчики получают FFmpeg автоматически через `scripts\download-ffmpeg.ps1` или через `winget`.

### 5.4. Ошибки интерфейса, WPF, Direct3D и Windows

#### 🔴 Ошибка 5.4.1: Не работает Drag & Drop (курсор перечеркнутого круга 🚫)
* **Симптомы:** При перетаскивании аудиофайлов или папок из Проводника в окно программы мышь показывает значок запрета, файлы не добавляются.
* **Причина:** OmniAudioStudio была запущена «От имени администратора» (Elevated Token), а Проводник Windows (`explorer.exe`) работает со стандартными правами. Механизм безопасности Windows UIPI (User Interface Privilege Isolation) аппаратно блокирует оконные сообщения `WM_DROPFILES` от низкопривилегированных процессов к высокопривилегированным.
* **Решение:** Запускайте приложение в штатном режиме обычного пользователя (двойным кликом), без прав администратора.

#### 🔴 Ошибка 5.4.2: Окно отображается со сплошным черным фоном (нет эффекта Mica)
* **Симптомы:** На окне отсутствует размытие подложки обоев рабочего стола.
* **Причина:**
  1. Эффект слюды (Mica Backdrop) аппаратно поддерживается операционной системой, начиная только с Windows 11 (сборка 22000+).
  2. В системных настройках Windows отключена опция эффектов прозрачности.
* **Решение:**
  - В Windows 11 откройте: «Параметры» ➔ «Персонализация» ➔ «Цвета» ➔ включите тумблер **«Эффекты прозрачности»**.
  - На Windows 10 программа автоматически и стабильно активирует адаптивную плоскую тему Fluent, предотвращая артефакты рендеринга.

#### 🔴 Ошибка 5.4.3: Сбой рендеринга видеоподсистемы (`UCEERR_RENDERTHREADFAILURE`)
* **Симптомы:** При запуске в виртуальной машине (VirtualBox, VMware, Hyper-V) или при подключении по RDP окно становится белым или аварийно закрывается.
* **Причина:** Драйвер виртуальной графики не поддерживает аппаратное 3D-ускорение WPF DirectX 9/11.
* **Решение:**
  Включите программный рендеринг через переменную среды Windows:
  ```powershell
  $env:WPF_DISABLE_GPU = "1"
  ```
  Либо добавьте параметр в реестр:
  `[HKEY_CURRENT_USER\Software\Microsoft\Avalon.Graphics]` ➔ `"DisableHWAcceleration"=dword:00000001`.

#### 🔴 Ошибка 5.4.4: Выпадающие списки (ComboBox) с белым фоном и черным текстом (Aero2 Fallback)
* **Симптомы:** В тёмной теме интерфейса выпадающие меню отрисовываются с белым классическим стилем Windows 7/Aero.
* **Причина:** В WPF при переопределении ItemContainerStyle без явного `BasedOn` стили сбрасываются до системного дефолта Aero2.
* **Решение:** В текущей кодовой базе проблема полностью решена в [`App.xaml`](file:///E:/antonantina/OmniAudioStudio-GitHub/OmniAudioStudio.Desktop/App.xaml) через явное наследование `BasedOn="{StaticResource DefaultComboBoxStyle}"`.

### 5.5. Ошибки производительности и многопоточности

#### 🔴 Ошибка 5.5.1: 100% загрузка процессора и зависание ПК при конвертации сотен файлов
* **Симптомы:** При добавлении очереди из 500+ треков компьютер начинает тормозить, кулеры шумят на максимальных оборотах.
* **Причина:** Без контроля конкурентности одновременный запуск десятков процессов FFmpeg исчерпывает кванты процессорного времени и память.
* **Решение:** Архитектура [`QueueManager.cs`](file:///E:/antonantina/OmniAudioStudio-GitHub/OmniAudioStudio.Desktop/Services/QueueManager.cs) использует асинхронный семафор `SemaphoreSlim`, инициализированный пулом реальных ядер процессора:
  ```csharp
  private readonly SemaphoreSlim _concurrencySemaphore = new(Math.Max(1, Environment.ProcessorCount));
  ```
  Это гарантирует оптимальный параллелизм, при котором процессор работает на максимальной эффективности без перегрева и зависания ОС.

#### 🔴 Ошибка 5.5.2: Переполнение дискового пространства при конвертации в Lossless WAV
* **Симптомы:** Конвертация альбома обрывается с ошибкой нехватки места на диске.
* **Причина:** Несжатый 24-битный звук занимает до 50 МБ на одну минуту воспроизведения (альбом из 15 треков может весить более 2 ГБ).
* **Решение:** Обращайте внимание на динамический бейдж расчётного веса в карточке трека (например, `[WAV · ~42.3 MB]`). Перед запуском конвертации больших очередей убедитесь в наличии свободного места на целевом диске.
