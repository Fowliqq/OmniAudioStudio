# OmniAudio Studio — справка пользователя

OmniAudio Studio — программа для конвертации аудиофайлов между популярными форматами. Она умеет работать как со сжатыми форматами вроде MP3 и OGG, так и с форматами без потерь вроде FLAC и WAV.

Этот файл — практическая справка для пользователя. Здесь собраны основные возможности программы, поддерживаемые форматы, информация о размере готовых файлов, инструкция для разработчиков по сборке и решения наиболее распространённых проблем.

## 1. Что умеет OmniAudio Studio

OmniAudio Studio предназначена для простой конвертации музыки и других аудиофайлов.

Программа использует FFmpeg для обработки аудио. Благодаря этому можно преобразовывать файлы между несколькими распространёнными форматами.

Основные возможности:

- конвертация аудиофайлов;
- обработка нескольких файлов подряд;
- отображение прогресса конвертации;
- отмена выполняющихся задач;
- чтение информации о треке и его длительности;
- отображение примерного размера результата до начала конвертации;
- отображение фактического размера готового файла после конвертации;
- автоматическое предотвращение случайной перезаписи исходного файла.

### Куда сохраняются файлы

Если Windows не позволяет сохранить результат в выбранную папку, используйте обычную пользовательскую папку, например:

- «Музыка»;
- «Загрузки»;
- «Документы»;
- рабочий стол;
- отдельную папку на диске `D:` или `E:`.

Не рекомендуется сохранять файлы непосредственно в системные каталоги Windows или `Program Files`.

## 2. Поддерживаемые форматы

### FLAC

**FLAC** — формат сжатия без потери качества.

Подходит, если нужно сохранить исходное качество звука и при этом уменьшить размер файла по сравнению с WAV.

В программе используется уровень сжатия **5** — это компромисс между размером файла и скоростью обработки.

### WAV

**WAV** — несжатый аудиоформат.

Он хорошо подходит для дальнейшей обработки звука, монтажа и хранения исходного материала, но занимает значительно больше места.

Программа использует PCM `16-bit`.

### ALAC

**ALAC (Apple Lossless)** — формат Apple для хранения звука без потерь.

Используется контейнер QuickTime / MP4 с расширением `.m4a`.

### AIFF

**AIFF** — несжатый аудиоформат, часто используемый в экосистеме Apple.

Для аудио используется PCM big-endian.

### MP3

**MP3** — один из самых распространённых форматов сжатого аудио.

Программа использует кодировщик LAME и поддерживает битрейт до **320 kbps**.

Также поддерживаются стандартные метаданные ID3v2.3 и ID3v1.

### AAC / M4A

**AAC** — формат сжатого аудио, который часто используется в `.m4a`.

Программа использует встроенный кодировщик AAC. Для M4A включена оптимизация, позволяющая быстрее начинать воспроизведение файла.

### OGG

**OGG Vorbis** — формат сжатого аудио.

Поддерживаются как постоянный, так и переменный битрейт.

### OPUS

**Opus** — современный аудиокодек, предназначенный для качественной передачи звука при небольшом размере файла.

В программе используется частота дискретизации **48 кГц**.

### WMA

**WMA (Windows Media Audio)** — формат Microsoft, который встречается в старых музыкальных коллекциях и устройствах.

Для него используется кодек `wmav2`.

## 3. Как рассчитывается размер файла

Перед началом конвертации программа показывает **примерный размер будущего файла**.

Это именно прогноз, а не гарантия точного размера.

После завершения конвертации программа проверяет настоящий размер файла на диске и заменяет примерное значение на фактическое.

Например:

```text
До конвертации:
[FLAC · ~1.0 MB]

После конвертации:
[FLAC · 982.4 KB]
```

Символ `~` означает, что размер является приблизительным.

### Почему размер может отличаться

Для форматов с потерями размер в основном зависит от:

- длительности трека;
- выбранного битрейта.

Для WAV и AIFF размер зависит от:

- длительности;
- частоты дискретизации;
- количества каналов;
- разрядности.

Для FLAC и ALAC размер зависит от того, насколько хорошо исходный звук сжимается. Поэтому точный размер заранее определить невозможно.

### Пример

Трек продолжительностью 3 минуты при битрейте 320 kbps в MP3 будет занимать примерно 7,2 МБ.

Несжатый WAV такого же трека в стандартном CD-качестве (44,1 кГц, стерео, 16 бит) будет занимать примерно 31,7 МБ.

Поэтому перед конвертацией большого количества файлов стоит учитывать выбранный формат.

## 4. Сборка программы для разработчиков

Этот раздел нужен только тем, кто собирает OmniAudio Studio из исходного кода.

Обычному пользователю эти команды выполнять не требуется.

### 4.1. Подготовка FFmpeg

В проекте предусмотрен скрипт, который автоматически скачивает и распаковывает FFmpeg:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\download-ffmpeg.ps1
```

После этого необходимые файлы FFmpeg должны находиться в папке `bin`.

### 4.2. Сборка проекта

Для обычной сборки выполните:

```powershell
dotnet build OmniAudioStudio.sln -c Release
```

### 4.3. Запуск тестов

Для запуска проверок:

```powershell
dotnet run --project OmniAudioStudio.Tests/OmniAudioStudio.Tests.csproj -c Release
```

### 4.4. Создание готового EXE

Чтобы собрать автономную версию для 64-битной Windows:

```powershell
dotnet publish OmniAudioStudio.Desktop/OmniAudioStudio.Desktop.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -o dist
```

Готовый файл появится здесь:

```text
dist/OmniAudioStudio.exe
```

Автономная сборка содержит необходимые компоненты .NET и поэтому не требует отдельной установки .NET Runtime на компьютере пользователя.

# 5. Решение проблем

Если программа показывает ошибку, сначала не стоит переустанавливать всё подряд.

Найдите текст ошибки в этом разделе и выполните указанные действия.

---

## 5.1. FFmpeg и ошибки обработки аудио

### FFmpeg не найден

**Что происходит**

При запуске конвертации программа сообщает, что `ffmpeg.exe` не найден.

**Почему**

Программа не смогла найти FFmpeg в доступных местах.

**Что сделать**

Если это рабочая копия проекта, проще всего выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\download-ffmpeg.ps1
```

Также FFmpeg можно установить через Windows Package Manager:

```powershell
winget install Gyan.FFmpeg
```

Ещё один вариант — поместить `ffmpeg.exe` и `ffprobe.exe` в папку:

```text
bin\
```

---

### Windows блокирует FFmpeg

**Что происходит**

Windows сообщает, что файл был получен из Интернета и заблокирован. Иногда FFmpeg может завершаться с кодом:

```text
-1073741819
```

**Почему**

Windows может автоматически добавлять к скачанным файлам отметку безопасности.

**Что сделать**

Откройте PowerShell в папке проекта и выполните:

```powershell
Unblock-File .\bin\ffmpeg.exe
Unblock-File .\bin\ffprobe.exe
```

Если файл блокирует сторонний антивирус, проверьте его уведомления и настройки доверенных приложений.

---

### «Invalid data found when processing input»

**Что происходит**

Конвертация завершается ошибкой, а в сообщении появляется:

```text
Invalid data found when processing input
```

**Почему**

Обычно это означает, что исходный файл:

- повреждён;
- скачан не полностью;
- имеет неправильное содержимое;
- защищён DRM.

**Что сделать**

Попробуйте открыть файл другим плеером.

Для дополнительной проверки можно использовать `ffprobe`:

```powershell
.\bin\ffprobe.exe "путь_к_файлу.mp3"
```

Если файл повреждён — скачайте или получите его заново.

Если файл защищён DRM, его необходимо легально получить в формате, который можно использовать без такой защиты.

---

### OPUS не использует выбранные 320 kbps

**Что происходит**

При выборе OPUS и высокого битрейта программа использует значение до 256 kbps.

**Почему**

Это связано с настройками кодека, используемого проектом.

**Что делать**

Ничего. Если программа сама ограничивает значение до 256 kbps, это штатное поведение текущей реализации.

---

### В WAV не отображается исполнитель или название

**Что происходит**

После конвертации в WAV некоторые старые устройства или плееры не показывают название трека и исполнителя.

**Почему**

Поддержка метаданных в WAV зависит от конкретного плеера или устройства. Старые устройства могут не читать используемый тип метаданных.

**Что делать**

Если важна совместимость метаданных, попробуйте:

- **FLAC** — если нужен звук без потерь;
- **MP3** — если файл должен воспроизводиться на большом количестве старых устройств.

## 5.2. Проблемы с файлами и сохранением

### Файл используется другой программой

**Ошибка может выглядеть так:**

```text
The process cannot access the file because it is being used by another process
```

**Почему**

Файл может быть открыт или воспроизводиться другой программой. Также его может временно использовать облачный сервис.

Например:

- AIMP;
- VLC;
- Windows Media Player;
- OneDrive;
- Яндекс Диск;
- Dropbox;
- Google Drive.

**Что сделать**

1. Закройте плеер или остановите воспроизведение.
2. Если используется облачная синхронизация — временно приостановите её.
3. Попробуйте сохранить результат в обычную локальную папку.

Например:

```text
D:\Music_Converted
```

---

### Слишком длинный путь к файлу

**Что происходит**

Windows выдаёт ошибку при работе с файлом, у которого очень длинный путь или слишком много вложенных папок.

**Что сделать**

Для начала попробуйте переместить исходный файл ближе к корню диска.

Например вместо:

```text
C:\Users\User\Documents\Music\Downloads\Artists\Albums\2026\...\track.flac
```

используйте:

```text
D:\Music\track.flac
```

Если проблема сохраняется, в Windows можно включить поддержку длинных путей.

Для этого PowerShell, запущенный от имени администратора, должен выполнить:

```powershell
Set-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name 'LongPathsEnabled' -Value 1
```

После этого может потребоваться перезагрузка Windows.

---

### Windows не разрешает сохранить файл

**Что происходит**

Появляется ошибка доступа при сохранении.

**Почему**

Windows защищает некоторые системные каталоги от записи обычными приложениями.

Особенно это касается:

```text
C:\
C:\Program Files\
```

и других системных папок.

**Что сделать**

Выберите для сохранения одну из обычных папок:

```text
Музыка
Загрузки
Документы
Рабочий стол
D:\
E:\
```

---

### Программа не перезаписывает исходный файл

Это нормальное поведение.

Если результат должен сохраниться в ту же папку и имя файла совпадает с исходным, программа автоматически меняет имя результата.

Например:

```text
audio.flac
```

станет:

```text
audio_converted.flac
```

Это сделано для того, чтобы случайно не удалить исходный файл.

## 5.3. Ошибки сборки и публикации

### NETSDK1045 — не поддерживается .NET 8

**Что происходит**

При сборке появляется ошибка:

```text
NETSDK1045: The current .NET SDK does not support targeting .NET 8.0
```

**Почему**

Установлена слишком старая версия .NET SDK.

**Что сделать**

Установите .NET 8 SDK:

```powershell
winget install Microsoft.DotNet.SDK.8
```

После установки проверьте версию:

```powershell
dotnet --version
```

Она должна начинаться с:

```text
8.0.
```

---

### Не найдены библиотеки WPF, CommunityToolkit или TagLib

**Что происходит**

Компилятор сообщает, что не может найти необходимые типы или пространства имён.

**Почему**

Зависимости NuGet могли не загрузиться.

**Что сделать**

Выполните:

```powershell
dotnet restore OmniAudioStudio.sln --force
```

Проверить источники NuGet можно командой:

```powershell
dotnet nuget list source
```

В списке должен присутствовать `nuget.org`.

---

### PublishSingleFile требует RuntimeIdentifier

**Что происходит**

При создании одного EXE появляется ошибка:

```text
PublishSingleFile requires a RuntimeIdentifier
```

**Почему**

При создании автономного EXE нужно указать, для какой платформы он собирается.

Для 64-битной Windows используйте:

```text
-r win-x64
```

Например:

```powershell
dotnet publish OmniAudioStudio.Desktop/OmniAudioStudio.Desktop.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o dist
```

---

### GitHub не принимает большой файл

**Что происходит**

При `git push` GitHub сообщает:

```text
File exceeds 100.00 MB limit
```

**Почему**

GitHub ограничивает размер отдельных файлов в обычном Git-репозитории.

Не стоит загружать туда большие `ffmpeg.exe` или готовые сборки программы.

**Что делать**

В проекте большие файлы должны быть исключены из Git через `.gitignore`.

Готовые большие версии программы лучше размещать в разделе:

**GitHub → Releases → Assets**

А не непосредственно в исходном коде репозитория.

## 5.4. Проблемы с интерфейсом Windows

### Не работает перетаскивание файлов

**Что происходит**

При попытке перетащить файл из Проводника в программу появляется значок запрета, и файл не добавляется.

**Частая причина**

Программа была запущена **от имени администратора**, а Проводник Windows работает с обычными правами.

**Что сделать**

Закройте программу и запустите её обычным двойным щелчком.

Не используйте «Запуск от имени администратора», если в этом нет необходимости.

---

### Нет эффекта Mica или окно выглядит иначе

**Что происходит**

В Windows 11 окно может не иметь ожидаемого эффекта полупрозрачности/размытия.

**Почему**

Эффект Mica зависит от версии Windows и системных настроек.

**Что сделать в Windows 11**

Откройте:

**Параметры → Персонализация → Цвета**

и включите:

**Эффекты прозрачности**

На Windows 10 используется альтернативное оформление без Mica.

---

### Окно становится белым или программа закрывается в виртуальной машине

**Что происходит**

Проблема может проявляться в VirtualBox, VMware, Hyper-V или при подключении через RDP.

**Почему**

Виртуальная графическая подсистема может некорректно работать с аппаратным ускорением WPF.

**Что сделать**

Попробуйте отключить аппаратное ускорение для WPF:

```powershell
$env:WPF_DISABLE_GPU = "1"
```

Также в Windows можно отключить аппаратное ускорение WPF через соответствующий параметр реестра.

---

### Выпадающие списки выглядят неправильно

**Что происходит**

В тёмной теме отдельные выпадающие меню могут неожиданно отображаться со светлым фоном и тёмным текстом.

**Что делать**

Если это происходит в текущей версии проекта, проблема относится к оформлению интерфейса, а не к вашим аудиофайлам или настройкам Windows.

В текущей кодовой базе эта проблема уже учитывается стилями интерфейса.

## 5.5. Производительность и место на диске

### Компьютер сильно загружается при конвертации большого количества файлов

**Что происходит**

При обработке большой очереди файлов процессор может быть загружен почти полностью, а вентиляторы — работать заметно активнее.

**Почему**

Конвертация аудио — ресурсоёмкая операция. При большом количестве файлов программа может обрабатывать несколько задач одновременно.

**Что делать**

Если компьютер начинает заметно тормозить:

1. не запускайте слишком много конвертаций одновременно;
2. обрабатывайте большие коллекции несколькими партиями;
3. убедитесь, что на компьютере достаточно свободной памяти и места на диске.

При обычной работе программы высокая загрузка процессора во время конвертации сама по себе не означает неисправность.

---

### Не хватает места на диске при конвертации в WAV

**Что происходит**

Конвертация внезапно останавливается из-за нехватки свободного места.

**Почему**

WAV не использует обычное сжатие, поэтому файлы получаются значительно больше MP3, AAC или FLAC.

Например, трёхминутный стереотрек в стандартном CD-качестве занимает около **31,7 МБ** в несжатом WAV.

При большом количестве файлов размер быстро увеличивается.

**Что делать**

# 6. Проект и исходный код

Если вы работаете с исходниками OmniAudio Studio, основные части проекта находятся в следующих папках:

```text
OmniAudioStudio/
├── assets/                    # Иконки и графические ресурсы
├── bin/                       # Локальные файлы FFmpeg
├── scripts/                   # Скрипты установки, сборки и тестирования
├── OmniAudioStudio.Desktop/  # Основное приложение
└── OmniAudioStudio.Tests/    # Тесты
```

В папке приложения находятся интерфейс, логика конвертации, работа с очередью файлов и чтение информации об аудио.

Папка `scripts` содержит готовые скрипты для загрузки FFmpeg, сборки проекта и запуска тестов.

Папка `OmniAudioStudio.Tests` предназначена для проверки основных компонентов программы.
